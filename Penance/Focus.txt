STEP 5 — WALK / IDLE ANIMATION LOGIC
==================================================

Goal:
When the player walks, the feet animate.
When the player stops, the walking animation stops.

Create/update:
ABP_Player

Variables:
- Speed
- Direction
- bIsMoving
- bIsSprinting
- bIsCrouching
- bIsGrounded
- TurnYawDelta
- bIsTurningInPlace

Animation update logic:
1. Get Velocity.
2. Use VectorLengthXY for Speed.
3. If Speed > 5 to 10 UU/s:
   bIsMoving = true
4. If Speed <= 5 to 10 UU/s:
   bIsMoving = false
5. If bIsMoving false:
   play Idle
6. If bIsMoving true:
   play Walk / locomotion blendspace

Movement speed targets:
- Walk: 250 UU/s
- Sprint: 550 UU/s
- Crouch: 140 UU/s

Reason:
Unreal uses centimeters.
1 Unreal Unit = 1 centimeter.
2.5 m/s = 250 UU/s.
5.5 m/s = 550 UU/s.
1.4 m/s = 140 UU/s.

STEP 6 — TURNING MUST BE TAKEN INTO CONSIDERATION
==================================================

Goal:
Turning should not look broken.
The player should not slide, twist weirdly, or keep using only forward walk when rotating.

Need to handle two types of turning:

A. Turning while moving
B. Turning in place while standing

----------------------------------------
A. Turning while moving
----------------------------------------

Use Direction variable:
Direction = Calculate Direction(Velocity, ActorRotation)

Use a 2D locomotion BlendSpace if possible:
BS_Player_Locomotion_2D

BlendSpace axes:
- Speed
- Direction

Suggested Direction values:
- -180 = backward
- -90 = strafe left
- 0 = forward
- 90 = strafe right
- 180 = backward

If only forward walk animation exists:
- Use forward walk for now.
- Still calculate Direction so the system is ready.
- Avoid extreme sideways foot sliding by rotating character toward movement direction or limiting visible strafe movement.

Recommended first implementation:
- Use CharacterMovement orient/rotation settings consistently.
- If first-person uses controller yaw, keep body aligned with camera yaw or smoothly follow camera yaw.
- Do not let the body face a different direction than the camera for too long.

----------------------------------------
B. Turning in place
----------------------------------------

When Speed is near 0 but camera/controller yaw changes:
- The upper body/camera turns immediately.
- The lower body should not look like it is walking.
- Optional: play a turn-in-place animation later.

For now:
If Speed <= 10 UU/s:
- stay in Idle
- rotate body smoothly toward camera/control yaw
- do not play walk animation

Future if turn animations exist:
- TurnLeft_90
- TurnRight_90
- TurnLeft_180
- TurnRight_180

Turn-in-place logic:
1. Store body yaw.
2. Compare camera/control yaw to body yaw.
3. TurnYawDelta = normalized yaw difference.
4. If abs(TurnYawDelta) > 45 degrees and Speed < 10:
   bIsTurningInPlace = true
5. Play left/right turn-in-place animation if available.
6. If no turn animation exists, smoothly rotate body root toward camera yaw.

Important:
Do not make the feet walk in place just because the player rotates the mouse.
Mouse turning should rotate orientation, not trigger walk animation.
