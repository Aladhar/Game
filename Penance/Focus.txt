STEP 5 — WALK / IDLE ANIMATION LOGIC
==================================================

Goal:
When the player walks, the feet animate.
When the player stops, the walking animation stops.

Create/update:
ABP_Player

Variables:
- Speed
- Direction
- bIsMoving
- bIsSprinting
- bIsCrouching
- bIsGrounded
- TurnYawDelta
- bIsTurningInPlace

Animation update logic:
1. Get Velocity.
2. Use VectorLengthXY for Speed.
3. If Speed > 5 to 10 UU/s:
   bIsMoving = true
4. If Speed <= 5 to 10 UU/s:
   bIsMoving = false
5. If bIsMoving false:
   play Idle
6. If bIsMoving true:
   play Walk / locomotion blendspace

Movement speed targets:
- Walk: 250 UU/s
- Sprint: 550 UU/s
- Crouch: 140 UU/s

Reason:
Unreal uses centimeters.
1 Unreal Unit = 1 centimeter.
2.5 m/s = 250 UU/s.
5.5 m/s = 550 UU/s.
1.4 m/s = 140 UU/s.

STEP 6 — TURNING MUST BE TAKEN INTO CONSIDERATION
==================================================

Goal:
Turning should not look broken.
The player should not slide, twist weirdly, or keep using only forward walk when rotating.

Need to handle two types of turning:

A. Turning while moving
B. Turning in place while standing

----------------------------------------
A. Turning while moving
----------------------------------------

Use Direction variable:
Direction = Calculate Direction(Velocity, ActorRotation)

Use a 2D locomotion BlendSpace if possible:
BS_Player_Locomotion_2D

BlendSpace axes:
- Speed
- Direction

Suggested Direction values:
- -180 = backward
- -90 = strafe left
- 0 = forward
- 90 = strafe right
- 180 = backward

If only forward walk animation exists:
- Use forward walk for now.
- Still calculate Direction so the system is ready.
- Avoid extreme sideways foot sliding by rotating character toward movement direction or limiting visible strafe movement.

Recommended first implementation:
- Use CharacterMovement orient/rotation settings consistently.
- If first-person uses controller yaw, keep body aligned with camera yaw or smoothly follow camera yaw.
- Do not let the body face a different direction than the camera for too long.

----------------------------------------
B. Turning in place
----------------------------------------

When Speed is near 0 but camera/controller yaw changes:
- The upper body/camera turns immediately.
- The lower body should not look like it is walking.
- Optional: play a turn-in-place animation later.

For now:
If Speed <= 10 UU/s:
- stay in Idle
- rotate body smoothly toward camera/control yaw
- do not play walk animation

Future if turn animations exist:
- TurnLeft_90
- TurnRight_90
- TurnLeft_180
- TurnRight_180

Turn-in-place logic:
1. Store body yaw.
2. Compare camera/control yaw to body yaw.
3. TurnYawDelta = normalized yaw difference.
4. If abs(TurnYawDelta) > 45 degrees and Speed < 10:
   bIsTurningInPlace = true
5. Play left/right turn-in-place animation if available.
6. If no turn animation exists, smoothly rotate body root toward camera yaw.

Important:
Do not make the feet walk in place just because the player rotates the mouse.
Mouse turning should rotate orientation, not trigger walk animation.

Implement a smoother Player locomotion animation flow for the visible first-person body.

Current problem:
The Player currently visually walks backwards only. This happens when walking forward or backward. The current walk animation/logic is not direction-aware enough.

Goal:
Create a clean player locomotion flow:
Idle → StartWalk → WalkLoop → StopWalk → Idle
Also handle turning in place, forward movement, backward movement, and smooth transitions.

Use the most recent fixed Player model/animation build:
- Penance/Built/Blender/Player_adaptive_REBUILT_ANIM.blend
- Penance/Built/FBX/SK_Player_Adaptive_REBUILT_ANIM.fbx
or the newest equivalent fixed Player file.

==================================================
PART 1 — FIX FORWARD/BACKWARD DIRECTION
==================================================

First inspect the model forward direction.

Unreal rule:
- Character forward should be +X in Unreal.
- Pressing W should move the character forward.
- Player feet should visually step forward when moving forward.
- Pressing S should use backward walking logic, not the same broken forward animation.

Check:
1. Is the mesh facing the correct direction in Unreal?
2. Is the skeleton/root facing the correct direction?
3. Is the walk animation authored backwards?
4. Is the Animation Blueprint using the same walk animation for forward and backward?

If the mesh or skeleton is rotated 180 degrees incorrectly:
- Fix the mesh/component relative rotation or export orientation.
- Do not hack the animation unless the model forward axis is correct first.

If the animation itself is backwards:
- Create a corrected Walk_Forward_Loop.
- Create a separate Walk_Backward_Loop.
- Do not use the backwards-looking walk for both W and S.

PART 2 — CREATE IDLE OPTIONS
==================================================

Create or verify these idle animations:

1. Idle_FeetTogether
- Default idle.
- Feet under hips.
- Toes forward.
- Knees slightly bent.
- Body relaxed.
- This should not look like the player froze mid-step.

2. Idle_Staggered
- Optional variation.
- One foot slightly forward.
- One foot slightly back.
- Subtle horror/nervous stance.
- Use only as idle variation, not the default every time.

The player should usually stop into Idle_FeetTogether unless the current stop pose naturally chooses another idle.

Create or verify:

StartWalk_Forward

Walk_Forward_Loop
- in-place forward walk
- believable at 250 UU/s
- feet do not deform

Walk_Backward_Loop

PART 4 — ANIMATION BLUEPRINT FLOW
==================================================

Update ABP_Player.

Variables:
- Speed
- ForwardSpeed
- RightSpeed
- Direction
- bIsMoving
- bMovingForward
- bMovingBackward
- bMovingLeft
- bMovingRight
- bIsTurningInPlace
- TurnYawDelta
- WalkPlayRate

Calculate:
Speed = VectorLengthXY(Velocity)
ForwardSpeed = dot(Velocity, ActorForwardVector)
RightSpeed = dot(Velocity, ActorRightVector)

Thresholds:
- Moving threshold: 10 UU/s
- Stop threshold: 5 UU/s
- Walk speed target: 250 UU/s

Logic:
If Speed <= 5:
    bIsMoving = false
    use Idle / TurnInPlace logic

If Speed > 10:
    bIsMoving = true

If ForwardSpeed > 10:
    use Forward walk logic

If ForwardSpeed < -10:
    use Backward walk logic

If abs(RightSpeed) > 10:
    use strafe or angled walk logic if available

Do not trigger walk animation from mouse turning alone.
Mouse turning while standing should use idle or turn-in-place.

==================================================
PART 5 — STATE MACHINE
==================================================

Create this state machine:

Idle
- Default state.
- Uses Idle_FeetTogether.
- Can optionally blend to Idle_Staggered after a delay.
- If Speed > 10 and ForwardSpeed > 0, transition to StartWalk_Forward.
- If Speed > 10 and ForwardSpeed < 0, transition to Walk_Backward_Loop or StartWalk_Backward if available.
- If Speed <= 10 and abs(TurnYawDelta) > 45, transition to TurnInPlace_Left or TurnInPlace_Right if available.

StartWalk_Forward
- Plays once.
- Transitions to Walk_Forward_Loop when nearly finished or Speed remains > 10.
- If player releases movement early, transition to StopWalk_Forward or Idle.

Walk_Forward_Loop
- Loops while ForwardSpeed > 10.
- Uses play rate Speed / 250 clamped 0.75 to 1.25.
- If Speed <= 5, transition to StopWalk_Forward.

Walk_Backward_Loop
- Loops while ForwardSpeed < -10.
- Uses play rate abs(ForwardSpeed) / 250 clamped 0.75 to 1.15.
- If Speed <= 5, transition to Idle or StopWalk_Backward if available.

StopWalk_Forward
- Plays once.
- Transitions to Idle_FeetTogether when finished.

TurnInPlace_Left / TurnInPlace_Right
- Only if Speed <= 10.
- Trigger based on camera/body yaw difference.
- If no turn animations exist yet, smoothly rotate the body toward the camera and stay in Idle.
